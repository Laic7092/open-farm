# 视觉升级：3/4 斜俯视路线

> 本文回答「现在的画面为什么平、分几刀把它改成 3/4 斜俯视、哪些方案已经否决」。
> 具体坐标 / 颜色 / 字段以 `tools/art/*.gd` 的 `##` 注释、`src/art/palette.gd`
> 与 `docs/art_pipeline.md` 为准；本文只做路线与取舍的记录。

## 1. 诊断：世界是 3/4，素材却是「立面」

游戏世界（TileMap + Y 排序 + 方向光）已经是斜俯视的，但大量素材是**正面立面**：

| 症状 | 证据 | 体感 |
| --- | --- | --- |
| 建筑只有一个正面 | `house.png` / `barn.png` 的屋顶是左右对称的三角，没有侧面 | 房子像舞台布景，转身就穿帮 |
| 树冠是正圆色块 | 高光居中、暗部均匀 | 树像一个贴纸，没有体积 |
| 栅栏 / 崖壁是平涂块 | `_fence` / `_cliff` 只有正面纹理 | 地面边界没有「立起来」 |
| 前后关系被整张图绑死 | 玩家与整棵树 / 整栋房做 Y 排序 | 站在建筑前头会被屋檐盖住，站到建筑后又整个人被挡没 |

结论：缺的不是分辨率或配色，而是**体积感**和**分层关系**。

## 2. 路线：3/4 斜俯视 + 身后淡出

**已拍板**：继续全脚本生成，不走手绘位图；整体维持 16 像素网格与明度分层调色板。

两个正交目标：

1. **每个大件都要有第二个体面**：房子看到正面 + 右侧面，树冠看到受光顶面与背光下缘，
   栅栏看到柱顶，崖壁看到上缘。统一光照方向：**左上受光、右下投影**。
2. **可通行区域不能被整张贴图挡住**：所有建筑（房子 / 谷仓 / 商店）统一走
   「身后淡出」——保留正常 Y 排序，人绕到北侧、贴图正要挡住人时整张降到
   ~42% 不透明度，离开恢复。树 / 栅栏 / 柜台 / 石头等暂不淡出，避免小件频繁
   闪动；局部 overlay（只把树冠 / 屋檐画在人上面）已整体否决：
   它会造成「身体在前、头被盖住」的割裂感。

### 已否决

- **手绘替换 PNG**：违背「仓库不放手工二进制素材」的规范，也不可复现。
- **给整张素材加描边 / 投影冒充体积**：只增加脏点，不解决面数。
- **旋转整张建筑贴图做 3/4**：像素会糊、落地线会偏，碰撞盒对不上。
- **第二套图集 / 第二套 source**：图集排版是单一事实来源，禁止分叉。
- **局部前景 overlay（树冠 / 屋檐单独压在人上）**：实测正面会出现「身体在前、
  头被盖住」；改为整张身后淡出，遮挡关系永远一致。

## 4. 本轮执行记录

### 4.1 3/4 立面重画

- **农舍 / 谷仓**（`tools/art/generate_props.gd`）
  - 右侧山墙向后上方退 9×6，出现真正的侧面。
  - 山墙三角 + 两坡屋顶（左坡受光、右坡背光），屋脊从前向后收。
  - 瓦垄与檐口斜边独立成线，烟囱坐在坡面上。
- **树 / 松树**（同文件）
  - 树冠改为「右下暗底 → 中间色 → 左上高光 → 下缘再压暗」，果实在受光侧。
  - 树干增加根盘；松树改三层三角，每层左亮右暗。
- **栅栏 / 崖壁**（`tools/art/generate_terrain.gd`）
  - 栅栏：一前一后两根柱子、柱顶高光、两道横杆带顶面与底面、柱脚投影。
  - 崖壁：顶部亮边 + 檐口阴影 + 竖向层理，底部收暗，读起来像凹进洞壁。

### 4.2 遮挡：建筑身后淡出

[WorldProp] 只保留一种遮挡机制，**无需改任何场景坐标**：

- 判定：摆件在 `WorldProp.BUILDING_GROUP`（`groups=["building"]`）里、是实心的
  （`WorldProp.passable == false`），且玩家落在它的纵向投影内、在它北侧（身后）；
  横向允许「碰撞盒半宽 + 10px」。
- 行为：`_process` 把 `modulate.a` 平滑推向 `behind_alpha`（默认 0.42），离开恢复。
- 阴影：Godot 2D 的 `DirectionalLight2D` 阴影永远无限长，所以方向光只做平行光、
  不开阴影；脚下投影改由 `WorldProp` 的软椭圆假影子画，正面时摆件照常 Y 排序，
  玩家完整在前。
- 范围：暂时只开放给建筑；树 / 栅栏 / 柜台 / 石头不淡出，避免小件频繁闪动。
- 建筑逐件开关：`fade_when_behind`；手感：`behind_alpha` / `fade_speed`。

早期版本还给树冠 / 屋檐生成过 `fg_<名字>.png` 前景 overlay，现已在 `WorldProp`、
`generate_props.gd`、测试与文档里**整体移除**；`assets/sprites/props/` 下不再有 `fg_` 素材。

### 4.4 水域：从瓦片到形状

旧水面是地面 `TileMapLayer` 里的三张瓦片（深水 / 水岸 / 浅滩），
由 `GroundPainter.water(area, shore_rows)` 铺：只能摆方形水池、只有上缘有岸，
而且 `WATER_EDGE` 是「水在上、沙在下」的立面画法，读不出俯视感。
本轮把它整个换成形状：

- **曲线**：`src/world/water_shape.gd` 生成闭合折线（圆角矩形 / 椭圆 /
  正弦扰动的有机水塘），16px 格子下的岸线不再是 45° 台阶。
- **俯视**：`tools/art/generate_water.gd` 按"到岸线的距离"逐像素烘贴图——
  越往中间水越深（浅 → 中 → 深三档），左上内侧压岸沿暗带（岸比水面高）、
  右下内侧提亮，沿岸一圈被噪声打断的浪花。
- **动态**：`WaterField._draw()` 逐帧画岸边浪花的呼吸、水波与水面碎光；
  小池塘用水波圈向岸扩散，海面则用横向浪线（同心圈在大水面上会读成方框）。
- **碰撞**：`WaterField` 按同一份形状生成 `StaticBody2D` + `CollisionPolygon2D`
  （物理层 1），玩家与 `NpcNavigator` 一起受益；木栈桥用
  `WaterLayout.Body.walkways` 从碰撞里挖出一条通道，桥面另铺一层 `TileMapLayer`
  盖在水面之上。
- **代价**：水下那几格不再是水面瓦片，所以 `FloraField._can_place()` 要单独问
  一次 `WaterField.is_water()`，否则野生植被会长到海里。
- **规范**：`docs/art_pipeline.md` §2.8；形状 / 碰撞由
  `tests/unit/test_water_shape.gd` 与 `test_assets.gd` 守住。
