# 未来开发方向（Roadmap）

> 面向维护者与编码 Agent 的**方向性规划**，不是承诺，也不是权威规格：数值、字段与规则一律以
> `data/**/*.tres`、代码顶部 `##` 注释与各专项文档为准。本文只回答两件事：**下一步做什么**、**为什么是这个顺序**。
>
> 现状证据散落在 `README.md`「已知限制」与各脚本的 `##`；本文不抄写它们，只做取舍与排序。

## 0. 怎么用这份文档

- 决定「先做什么」：看 §7 里程碑路线图。
- 决定「某个方向具体做什么」：看 §2~§5 的方向表，每行都带现状证据与主要入口。
- 需要拍板的事项集中在 §6；定下来后请顺手回填本文与 `README.md`。
- 完成一项就在对应行标注状态，避免规划与代码长期脱节。

## 1. 现状定位：缺口不在「系统数量」，在「系统深度」

项目已把骨架打通（v0.3，`src/` 约 14.3k 行 GDScript、369 个单元测试、Web / Windows 双导出、
分层 + 依赖注入 + 领域事件 + `.tres` 数据驱动）。真正的瓶颈集中在四处：

| 缺口类型 | 证据 | 体感 |
| --- | --- | --- |
| 内容量少 | `data/`：3 作物 / 2 牲畜 / 10 鱼 / 7 植被 / 5 节日 / 5 事件 / 2 商店 | 十几个小时见底 |
| 循环太浅 | 钓鱼无拉扯；牲畜不死不繁殖；恋爱是自动里程碑 | 每个系统「点一下就完」 |
| 明确留白 | `ToolData.tier` 注释「骨架阶段仅保留字段」；`dialogue_line.gd`「分支对话留待后续」；`shipping_bin.gd` 自认「一次性全卖」简化；全仓无 cooking / recipe / 博物馆 / 任务 / 成就 | 缺长期目标与自我表达 |
| 底座债 | `README.md` 已知限制：场景常驻内存、水无碰撞、NPC 不避让、事件仅日结转判定、单存档槽、纯键盘 | 内容一多就碰壁 |

由此得到的排序原则：**补深度 → 扩内容 → 还债 → 产品化**，而不是再挂一个并列的新系统。

## 2. 方向 A：把现有循环做「厚」（优先级最高）

现有系统都停在「能用」而非「好玩」。这一步不引入全新的并列玩法，只把已有循环加厚——
因为作物 / 牲畜 / 鱼 / 矿石一旦互相咬合，就会长出一条经济闭环：
矿石 → 工具 → 更深的地 → 料理 → 体力 → 更长的一天。

| 系统 | 现状（证据） | 目标 | 主要入口 |
| --- | --- | --- | --- |
| 料理 / 食谱 | 无，全仓 grep 零命中 | 作物 / 畜产品 / 鱼互为原料；回复与短时增益 | `data/recipes/`、`src/farm/cooking_rules.gd`、农舍灶台 |
| 工具升级 | `ToolData.tier` 字段已预留但无人写入 | 矿石 → 铁匠 → 铜/铁/金锄头、水壶容量、钓竿等级 | `src/data/tool_data.gd`、`data/tools/`、`data/items/`、铁匠 NPC |
| 钓鱼 | 「等咬钩 → 按一次」；`fishing_rules.gd` 仅有咬钩延时 / 窗口 | 拉扯小游戏（判定写成纯函数以保住可测性）、鱼饵、鱼竿等级、体长记录 | `src/farm/fishing_rules.gd`、玩家钓鱼状态 |
| 牲畜 | 2 种（鸡 / 牛）；不死亡、不繁殖；好感不产物品质 | 繁殖（怀孕 → 幼崽）、老年 / 死亡、好感影响星级、放牧省干草 | `src/farm/animal_husbandry.gd`、`data/animals/` |
| 作物 | 3 种；无品质 / 肥料 / 温室 | 星级品质、肥料、连作枯萎、温室、每季 5~8 种、果树 | `src/farm/crop_growth.gd`、`data/crops/`、`tools/art/generate_crops.gd` |
| 出货 | `shipping_bin.gd` 一次性全卖 | 逐件投放 + 隔天结算（注释已写明接口不变即可替换） | `src/world/shipping_bin.gd` |

## 3. 方向 B：补「类型必备」的广度系统

深度到位后再铺广度；这些系统大多能在现有框架上加，不需要新架构。

| 系统 | 作用 | 复用什么 |
| --- | --- | --- |
| 博物馆 / 图鉴 | 鱼 / 作物 / 矿石 / 料理 / 文物可捐赠收录，给长线收集目标 | 纯数据驱动，几乎零新机制 |
| 委托板 / 支线 | NPC 每日或每周发布委托（要 3 个鸡蛋、钓一条鲶鱼） | `data/npcs/`、`data/dialogue/` |
| 好感度心事件 | 把「满足条件自动推进」换成每颗心解锁一段手写事件 | `src/event/event_rules.gd`、`data/events/`、`RelationshipStore` |
| 分支对话 | 选项 → 分支 → flag，叙事深度的基础 | `src/data/dialogue_line.gd`（已留口子） |
| 节日小游戏 | 现在到场按 `E` 即结束；改为赛跑 / 钓鱼赛 / 料理赛 / 烟花选美 | `src/event/festival_ground.gd`、`festival_rules.gd` |
| 长期村庄目标 | 社区中心式「贡献清单」，替代「攒钱到没处花」 | 新增计数 + 一次性事件 |
| 房屋扩建 / 家具 | 金钱出口与自我表达 | `data/buildings/`、场景摆放 |

## 4. 方向 C：还底座债（做内容与平台之前必须还）

| 债 | 建议 | 相关入口 |
| --- | --- | --- |
| 世界场景常驻内存 | 状态外置 + 懒加载 / 按需卸载 | `src/main/world_host.gd` |
| 水域无碰撞 | 补碰撞层 / 水域导航，钓鱼与寻路同时受益 | 场景 + `src/core/water_kind.gd` |
| NPC 不互相避让 | 动态占用网格 + 局部避让 | `src/npc/npc_navigator.gd`、`src/core/grid_pathfinder.gd` |
| 事件仅日结转判定 | 区域 / 实时触发（`Area` → `EventBus` → 规则） | `src/event/event_rules.gd` |
| 单存档槽 | 多槽 + 自动存档 + 版本迁移（JSON 已带版本号） | `src/autoload/save_manager.gd`、`src/core/persistence.gd` |
| 字体约 1100 字形子集 | 动态字形加载或打包完整 CJK，避免生僻字方块 | `tools/art/generate_font.gd` |
| 纯键盘、鼠标隐藏 | 手柄映射 + 可选触摸，为 Deck / 移动端铺路 | `project.godot` InputMap、`src/core/pointer_input.gd` |

额外的高杠杆项：

- **内容包 / Mod**：一切走 id + `.tres`，把数据来源做成可替换目录（如 `user://mods`）即可换来社区生态。
- **数据校验 lint**：检查 id 引用、日程点、商店库存是否有效；放进 `tools/`，内容一多才不会烂。
- **平衡模拟器**：headless 跑「N 天最优策略」看收入曲线，替代手工拍数值——契合本仓「规则可脱离引擎测试」的哲学。
- **本地化扩展**：i18n 已就位，加语言基本只补 CSV。

## 5. 方向 D：产品化与平台

- **Web 试玩版**：`export_presets.cfg` 已有 Web preset，做垂直切片放 itch.io 收集反馈，成本最低。
- **Steam**：成就（图鉴 / 结婚 / 首年）、云存档、Deck 手柄支持。
- **移动端**：受众大，但需要输入层改造（当前纯键盘）。
- **可访问性**：色盲调色板、字号调节、按键重映射。

## 6. 需要拍板的战略抉择

1. **美术路线**：继续全脚本生成（保住「纯代码仓库」身份，但质感上限明显），还是引入手绘 / 委托素材、脚本生成退为占位？
   折中：脚本生成继续升级（更多帧、季节变体、色板），关键角色与宣传图用手绘。
2. **体量目标**：「精致小体量垂直切片」（1 个完整年、约 30 小时）还是「对标牧场物语的完整版」（多年、全套系统）？这直接决定优先级。
3. **平台优先级**：`Web 试玩 → Steam 单机` 是稳妥主线；移动 / 联机是另一个量级。

## 7. 里程碑路线图

| 版本 | 主题 | 关键交付 |
| --- | --- | --- |
| v0.4 | 循环深度 | 料理 + 食谱、工具升级 + 矿石、钓鱼小游戏、牲畜繁殖 / 品质 |
| v0.5 | 内容广度 | 每季 6 种作物、博物馆图鉴、委托板、商店扩容 |
| v0.6 | 叙事 | 好感度心事件、分支对话、节日小游戏、长期村庄目标 |
| v0.7 | 底座 | 场景卸载、多存档槽、水碰撞、事件实时触发 |
| v0.8 | 产品化 | Web 试玩版、手柄、可访问性、数据校验 lint |
| v1.0 | 完整一年 | 数值平衡、教程、成就、Steam 发行 |

若只做一件事：先做 **v0.4 的料理 + 工具升级 + 钓鱼小游戏**。它把已有作物 / 牲畜 / 鱼 / 矿石串成互相咬合的经济闭环，
单位投入的体感回报最高，且完全贴合本仓「数据驱动 + 纯规则可测」的架构，不会引入循环依赖。

## 8. 落地约束（新系统必须延续的架构约定）

无论做哪个方向，都要延续 `docs/architecture.md` 的分层与下面这些硬约束，否则技术债会反噬：

- 规则写成**纯静态函数或 RefCounted**，可脱离引擎在 `tests/unit/` 覆盖；场景节点只做翻译与呈现。
- 内容数据只认 **id**，新增内容优先只加 `data/**/*.tres`；新增汉字 / 文案后必须重跑 `build_assets.sh`。
- 新状态参与存档时实现 `to_dict` / `from_dict` 并 `Persistence.register()`；跨系统状态放进对应服务，不要新开 Autoload。
- UI 只订阅 `EventBus`（或其领域对象），不反向调用玩法代码。
- 收尾标准：`tools/check.sh` 通过 + 更新相关 `##` 注释 / `docs/` + 回填 `README.md`「扩展入口」表。
